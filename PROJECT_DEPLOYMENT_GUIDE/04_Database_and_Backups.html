الدليل 04 • قواعد البيانات والأمان
إدارة قواعد البيانات والنسخ الاحتياطي لـ LawSaaS
حماية بيانات المكاتب، تشغيل الترقية التلقائية، وعمليات النسخ والاسترجاع

1. بيئتا قاعدة البيانات في مشروع LawSaaS

يستخدم نظام LawSaaS تقنية SQLAlchemy ORM المرنة، والتي تتيح للمشروع العمل مع بيئتين مختلفتين دون تغيير كود الاستعلامات:

المعيار البيئة المحلية (Development) بيئة الإنتاج السحابية (Production)
نوع المحرك SQLite (ملف محلي law_firm.db) PostgreSQL السحابي القوي (lawsaas_db)
السرعة والتنصيب فوري وسريع ولا يحتاج سيرفر مستقل. مخصص لتحمل ملايين السجلات والاتصالات المتزامنة.
رابط الاتصال (URL) sqlite:///./law_firm.db postgresql://lawsaas:pass@localhost:5432/lawsaas_db

2. كيف تعمل ترقية وتحديث الجداول تلقائياً (Auto-Migration)؟

يتميز مشروع LawSaaS بوجود محرك ترقية تلقائي مبتكر داخل database/database.py. عندما تضيف عموداً جديداً في نموذج database/models.py وتنشره على السيرفر، يقوم الكود عند بدء التشغيل بما يلي:

  1. فحص كافة الجداول في قاعدة بيانات الإنتاج.
  2. مقارنة الأعمدة الموجودة في قاعدة البيانات بالأعمدة المعرفة في كود بايثون.
  3. إذا وجد عموداً جديداً (مثل claim_amount أو target_authority)، يُنفذ تلقائياً استعلام:
    ALTER TABLE law_incoming_cases ADD COLUMN claim_amount VARCHAR;
  4. تتم هذه العملية بسلاسة تامة دون حذف أي بيانات سابقة أو التأثير على العملاء الحاليين!

3. كيفية أخذ نسخة احتياطية حية (Backup) لقاعدة البيانات

النسخ الاحتياطي الدوري هو صمام الأمان لأي منصة سحابية. لحفظ بيانات المكاتب والقضايا:

أ) على السيرفر الفعلي (PostgreSQL Backup)

أخذ نسخة احتياطية على السيرفر
# أخذ نسخة مدمجة ومضغوطة من قاعدة بيانات PostgreSQL: root@lawsaas-vps:~# docker exec -t lawsaas_db pg_dump -U lawsaas lawsaas_db > /opt/backups/lawsaas_backup_$(date +%Y%m%d).sql # يتم حفظ النسخة في مجلد آمن خارج الحاوية

ب) محلياً على جهازك (تصدير الجداول عبر السكربت)

# تشغيل سكربت التصدير الشامل المضمن في المشروع: PS > python export_all_databases.py # يقوم السكربت بحفظ كافة الجداول في ملفات CSV و SQL آمنة

4. كيفية استعادة النسخة الاحتياطية عند الطوارئ (Restore)

إذا حدث خطأ غير متوقع وأردت استعادة قاعدة البيانات تماماً كما كانت في النسخة الاحتياطية:

⚠️ تنبيه حرج قبل الاستعادة

استعادة النسخة الاحتياطية ستستبدل البيانات الحالية ببيانات النسخة. تأكد دائماً أنك تستعيد النسخة الصحيحة.

أمر استعادة قاعدة البيانات على السيرفر
# استرجاع ملف النسخة الاحتياطية إلى قاعدة بيانات PostgreSQL: root@lawsaas-vps:~# cat /opt/backups/lawsaas_backup_20261122.sql | docker exec -i lawsaas_db psql -U lawsaas -d lawsaas_db # بعد الاستعادة، أعد تشغيل التطبيق لتحديث الاتصالات: root@lawsaas-vps:~# docker restart lawsaas_app

5. إرشادات الأمان والحماية لبيانات المكاتب

  • منع الحذف الصلب (Soft Delete Enforced): لا تستخدم أمر DELETE المباشر في قواعد البيانات. اعتمد دائماً على تعيين is_deleted = 1 لتبقى كافة المعاملات محفوظة في الأرشيف.
  • عزل المكاتب الصارم (Tenant Isolation): تأكد أن كل استعلام SQL يتضمن دائماً شرط office_id == current_user.office_id لضمان عدم اطلاع أي مكتب محاماة على بيانات مكتب آخر.
  • حظر الملفات الاحتياطية من الوصول العام: إياك أن تحفظ ملفات .sql أو .dump داخل مجلد static/ أو templates/، لأن أي شخص قد يحملها من المتصفح! احتفظ بالنسخ في مجلد مستقل ومحمي مثل /opt/backups/.
