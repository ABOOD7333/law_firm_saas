الدليل الشامل لـ Git و GitHub للمبتدئين
دليل تأسيسي عملي: من فهم المفاهيم الأساسية وحتى إدارة الفروع والتعامل مع الأخطاء

1. ما هو Git وما هو GitHub؟ وما الفرق الجوهري بينهما؟

كثير من المبتدئين يخلطون بين Git و GitHub ويعتقدون أنهما شيء واحد. الحقيقة أنهما أداتان مختلفتان تعملان معاً:

المعيار Git (الأداة المحلية) GitHub (المنصة السحابية)
ما هو؟ برنامج مثبت على جهاز الكمبيوتر الخاص بك، وظيفته تسجيل تاريخ تعديلات الملفات مثل (آلة الزمن). موقع ويب وخدمة سحابية على الإنترنت تستضيف المستودعات التي تدار بواسطة Git لمشاركتها وحفظها.
أين يعمل؟ محلياً على جهازك (Offline) دون الحاجة لاتصال بالإنترنت. على خوادم شركة مايكروسوفت/GitHub وتتطلب اتصالاً بالإنترنت للوصول إليها.
المسؤولية تتبع التغييرات، إنشاء الفروع، دمج الأكواد، وتسجيل الالتزامات (Commits). النسخ الاحتياطي السحابي، إدارة الفرق، مراجعة الأكواد (Pull Requests)، والأتمتة (Actions).
المكافئ الواقعي دفتر يومياتك الشخصي الذي تدون فيه كل خطوة بيدك. المكتبة العامة أو الخزينة السحابية التي تضع فيها نسخة من دفترك ليعود إليها الجميع.

2. كيف تعرف المستودع المرتبط بمشروعك؟

لمعرفة رابط المستودع السحابي على GitHub المرتبط بمجلد مشروعك الحالي، افتح نافذة الأوامر (Terminal) في مجلد المشروع واكتب:

PowerShell / Bash
PS > git remote -v # النتيجة في مشروع LawSaaS الفعلي: origin https://ABOOD7333@github.com/ABOOD7333/law_firm_saas.git (fetch) origin https://ABOOD7333@github.com/ABOOD7333/law_firm_saas.git (push)

شرح النتيجة: كلمة origin هي الاسم المستعار الافتراضي للمستودع السحابي، والرابط يوضح أن مشروعك مرتبط بحساب ABOOD7333 في المستودع law_firm_saas.

3. دورة حياة الملفات في Git (المراحل الثلاث)

عندما تعدل أي ملف في مشروعك، يمر الملف بثلاث مناطق رئيسية قبل أن يصل إلى GitHub:

1
منطقة العمل المحلية (Working Directory)
الملفات التي فتحتها في المحرر وقمت بتعديلها أو إضافتها. تظهر باللون الأحمر عند فحص الحالة لأن Git رصد التغيير لكنه لم يجهزه للحفظ بعد.
2
منطقة التجهيز (Staging Area)
تصل إليها بعد تنفيذ أمر git add. تعني أنك اخترت هذه التعديلات بالتحديد لتكون جزءاً من الحزمة القادمة. تظهر باللون الأخضر.
3
المستودع المحلي المحفوظ (Local Repository)
تصل إليها بعد تنفيذ أمر git commit. هنا يُسجل التعديل نهائياً في سجل تاريخ المشروع المحلي برمز تجزئة فريد (Commit Hash) ورسالة وصفية.
4
المستودع السحابي (Remote GitHub)
تصل إليها بعد تنفيذ أمر git push. تُرسل الحزم المحفوظة من جهازك عبر الإنترنت لتستقر في خوادم GitHub.

4. الأوامر الأساسية اليومية بالتفصيل

أ) فحص التغييرات: git status و git diff

PS > git status # يخبرك: ما هو الفرع الحالي؟ ما هي الملفات التي عدلتها؟ وما هي الملفات الجديدة؟ PS > git diff # يوضح لك بالتفصيل الأسطر التي حذفتها (-) والأسطر التي أضفتها (+) داخل الأكواد

ب) تجهيز الملفات: git add

# لتجهيز ملف واحد محدد: PS > git add routers/incoming_cases.py # لتجهيز كافة الملفات المعدلة والجديدة دفعة واحدة: PS > git add .

ج) حفظ الالتزام: git commit

PS > git commit -m "إضافة حقول الدعاوى الجديدة وتحديث التوجيه" # الرمز -m اختصار لـ Message. اكتب دائماً رسالة واضحة تلخص ما قمت بعمله.

د) رفع التعديلات وسحبها: git push و git pull

# رفع تعديلاتك من جهازك إلى فرع main على GitHub: PS > git push origin main # سحب آخر التعديلات الموجودة على GitHub وتحديث جهازك بها: PS > git pull origin main

5. الفروع (Branches) وإدارتها باحتراف

ما هو الفرع؟ الفرع هو مسار عمل مستقل ومنعزل تماماً عن الكود الأصلي. تخيل أنك تبني ميزة تجريبية جديدة، بدلاً من تعديل كود main المستقر، تفتح فرعاً مستقلاً وتجرب فيه بحرية؛ إن نجحت دمجته، وإن فشلت حذفته دون أن يتأثر موقعك الحي!

الأمر الوظيفة العملية
git branch عرض قائمة بكافة الفروع المحلية مع وضع علامة (*) بجانب الفرع الفعال حالياً.
git checkout -b feature-name إنشاء فرع جديد باسم feature-name والانتقال إليه فوراً.
git switch main التبديل والرجوع إلى الفرع الرئيسي main.
git merge feature-name دمج تعديلات الفرع feature-name داخل الفرع الذي تقف عليه حالياً.
git branch -d feature-name حذف الفرع محلياً بعد الانتهاء من دمجه بنجاح.

6. أشهر أخطاء Git وحلولها السريعة للمبتدئين

⚠️ الخطأ الأول: Updates were rejected because the remote contains work (التعارض عند الرفع)

السبب: يوجد تعديل جديد على GitHub لم تسحبه إلى جهازك أولاً (قام به زميل أو تم تعديله على السيرفر).
الحل السحري: قم بسحب التعديلات أولاً ثم أعد الرفع:
git pull --rebase origin main ثم git push origin main

⚠️ الخطأ الثاني: تراجعت عن تعديلات ملف معين قبل عمل Commit

إذا عدلت ملفاً بالخطأ وأردت إلغاء كل تعديلاتك وإرجاعه تماماً كما كان في آخر Commit:
git restore path/to/file.py

💡 الخطأ الثالث: كتبت رسالة Commit خاطئة وتريد تعديلها

طالما أنك لم ترفع التعديل بعد بـ Push، يمكنك تعديل آخر رسالة عبر:
git commit --amend -m "الرسالة الصحيحة الجديدة"
