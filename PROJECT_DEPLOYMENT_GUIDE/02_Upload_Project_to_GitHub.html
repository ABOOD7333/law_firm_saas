الدليل 02 • التطبيق العملي للرفع
الدليل التطبيقي لرفع وتحديث LawSaaS على GitHub
خطوات عملية حقيقية خطوة بخطوة للعمل على مستودع ABOOD7333/law_firm_saas

1. تجهيز بيئة العمل المحلية على جهازك

في مشروع LawSaaS الفعلي، يوجد مسار عملك المحلي في المسار:
C:\Users\Roots\.gemini\antigravity\worktrees\law_firm1\analyze_missing_features

قبل أن تفكر في كتابة أي أمر رفع، هناك قاعدة أمنية ذهبية في هندسة البرمجيات: إياك أن ترفع ملفات الأسرار (.env) أو قواعد البيانات المحلية (.db) إلى GitHub!

التحقق من ملف .gitignore

ملف .gitignore هو الحارس الأمين؛ يخبر Git بالملفات والمجلدات التي يجب تجاهلها تماماً وعدم رؤيتها أو رفعها أبداً. تأكد دائماً أن الأسطر التالية موجودة داخله:

.gitignore
.env .env.local *.db *.sqlite3 __pycache__/ *.pyc uploads/ poppler/ .pytest_cache/

2. خطوات رفع التعديلات خطوة بخطوة (سيناريو حقيقي)

1
الخطوة الأولى: فتح نافذة الأوامر والتحقق من الحالة
افتح PowerShell في مسار المشروع واكتب git status لمعرفة الملفات التي قمت بتعديلها والتأكد من عدم وجود ملفات حساسة غير مرغوبة.
PS C:\...\law_firm1> git status
2
الخطوة الثانية: تجهيز الملفات (Staging)
أضف الملفات التي تريد رفعها. يفضل تحديد الملفات بالاسم لضمان الدقة، أو استخدام git add . إذا كنت واثقاً من نظافة كافة الملفات المعدلة.
PS C:\...\law_firm1> git add routers/incoming_cases.py database/models.py templates/incoming_cases/
3
الخطوة الثالثة: توثيق التعديل وحفظه محلياً (Commit)
احفظ التعديل برسالة معبرة وواضحة تشرح التحديث باللغة العربية أو الإنجليزية.
PS C:\...\law_firm1> git commit -m "تحديث واجهة القضايا الواردة وإضافة نموذج قيد الدعوى الجديد"
4
الخطوة الرابعة: سحب أي تحديثات جديدة لمنع التعارض (Pull)
قبل الرفع، تأكد أنك تملك أحدث نسخة عبر سحب أي تعديلات تم دمجها على السحابة.
PS C:\...\law_firm1> git pull origin main
5
الخطوة الخامسة: رفع التعديلات نهائياً إلى GitHub (Push)
أرسل التعديلات إلى مستودعك الرسمي على GitHub.
PS C:\...\law_firm1> git push origin main # سيظهر ناتج يوضح ضغط الكائنات ورفعها بنجاح: Enumerating objects: 15, done. Writing objects: 100% (15/15), 12.45 KiB | 2.49 MiB/s, done. To https://github.com/ABOOD7333/law_firm_saas.git 793d3b0..a1b2c3d main -> main

3. العمل الاحترافي عبر الفروع (Feature Branch Workflow)

في الشركات الكبرى، لا يرفع المطورون تعديلاتهم مباشرة إلى فرع main، بل ينشئون فرعاً باسم الميزة، يرفعونه إلى GitHub، ثم يفتحون طلب دمج (Pull Request) لمراجعة الكود قبل اعتماده. إليك الطريقة خطوة بخطوة:

# 1. إنشاء فرع جديد والتبديل إليه: PS > git checkout -b add-zatca-invoice-feature # 2. قم بتعديل أكوادك واختبرها محلياً... # 3. حفظ التعديل على الفرع الجديد: PS > git add . PS > git commit -m "إضافة باركود زاتكا في راوتر المحاسبة" # 4. رفع الفرع الجديد إلى GitHub: PS > git push -u origin add-zatca-invoice-feature

كيف تدمج التعديل عبر واجهة موقع GitHub؟

  1. ادخل إلى صفحة مستودعك: https://github.com/ABOOD7333/law_firm_saas
  2. ستجد شريطاً أصفر ينبهك بوجود فرع جديد مع زر أخضر يسمى Compare & pull request. اضغط عليه.
  3. اكتب وصفاً للتعديلات واضغط على Create pull request.
  4. بعد التأكد من سلامة الفحص التلقائي (CI)، اضغط على Merge pull request ثم Confirm merge.
  5. مبروك! أصبحت تعديلاتك مدمجة الآن في الفرع الرئيسي main وجاهزة للنشر على السيرفر!
