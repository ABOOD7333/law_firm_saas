الدليل 05 • استكشاف الأخطاء و Rollback
دليل استكشاف الأعطال والإصلاح والرجوع لإصدار سابق
حل مشكلات السيرفر، أخطاء 500 و 502، والتعافي السريع من أخطاء النشر

1. تشخيص وحل أشهر 5 مشاكل تواجه المطورين عند النشر

🔥 المشكلة 1: خطأ 502 Bad Gateway بعد النشر

المعنى: خادم Nginx يعمل بنجاح، لكنه عاجز عن الاتصال بتطبيق FastAPI لأن الحاوية متوقفة أو فشلت في الإقلاع.
خطوات التشخيص الفوري:
1. افحص حالة الحاوية: docker ps -a (ستجد حالتها Exited).
2. اقرأ سبب الانهيار: docker logs --tail 50 lawsaas_app
أشهر سبب: وجود خطأ تركيبي (SyntaxError) أو استيراد مفقود (ImportError) في ملف بايثون. أصلح الخطأ في الكود وأعد بناء الحاوية.

⚠️ المشكلة 2: خطأ 500 Internal Server Error في صفحة معينة

المعنى: الموقع يعمل، ولكن عند الدخول لصفحة محددة (مثل القضايا الواردة) يظهر خطأ 500.
السبب: وجود متغير ناقص في قالب Jinja2، أو استعلام قاعدة بيانات يستعلم عن حقل غير موجود.
طريقة الحل: افتح سجلات التطبيق أثناء تحديث الصفحة لمشاهدة الـ Traceback الدقيق:
docker logs -f lawsaas_app

💡 المشكلة 3: التعديلات لا تظهر في المتصفح بعد النشر

السبب: المتصفح يحتفظ بنسخة قديمة مؤقتة من ملفات الـ CSS والـ JavaScript (Browser Cache).
الحل السريع: اضغط في المتصفح على Ctrl + Shift + R أو Ctrl + F5 لفرض تحديث كامل بدون كاش، أو افتح نافذة تصفح خفي (Incognito).

2. السيناريوهات العملية الخمسة لإدارة التحديثات

السيناريو 1: عدلت قالباً أو صفحة HTML وأريد نشرها بسرعة

  1. عدل القالب محلياً واختبره.
  2. احفظ وادفع التعديل: git add . && git commit -m "تعديل واجهة القضايا" && git push origin main
  3. على السيرفر: cd /opt/lawsaas && git pull origin main
  4. أعد تشغيل التطبيق: docker restart lawsaas_app (لا حاجة لإعادة البناء الكامل لأن القوالب تُحدث فوراً).

السيناريو 2: أضفت ميزة جديدة تتضمن عموداً جديداً في قاعدة البيانات

  1. أضف العمود في database/models.py ومحرك الترقية التلقائية في database/database.py.
  2. ارفع التعديل إلى GitHub بـ git push origin main.
  3. على السيرفر: اسحب التعديلات وأعد بناء الحاوية:
    docker compose up -d --build app
  4. يقوم التطبيق عند انطلاقه بفحص الجدول وإضافة العمود تلقائياً.

السيناريو 3: حدث خطأ طارئ بعد النشر وأريد الرجوع فوراً لإصدار سابق (Rollback)

إذا نشرت تحديثاً وتسبب في مشكلة وتريد إرجاع الموقع خلال ثوانٍ إلى النسخة السابقة التي كانت تعمل:

خطوات الـ Rollback الفوري
# 1. الدخول لمجلد المشروع على السيرفر: root@lawsaas-vps:~# cd /opt/lawsaas # 2. عرض آخر التعديلات لمعرفة رقم الـ Commit السابق: root@lawsaas-vps:/opt/lawsaas# git log --oneline -n 5 # يظهر مثلاً: a1b2c3d (HEAD -> main) التحديث الجديد الذي سبب المشكلة 793d3b0 التحديث القديم المستقر # 3. العودة الفورية للإصدار القديم المستقر: root@lawsaas-vps:/opt/lawsaas# git checkout 793d3b0 # 4. إعادة تشغيل الحاوية فوراً: root@lawsaas-vps:/opt/lawsaas# docker compose up -d --build app # عاد موقعك الآن للعمل بسلام في أقل من دقيقة!
